# 해드리오 사이트 빌드

사이트는 정적 HTML입니다. 문구와 가격은 `src/`에서 고치고, 빌드하면 각 언어 페이지가 다시 만들어집니다.

## 파일 구조

| 위치 | 내용 |
| --- | --- |
| `src/site.json` | 가격(원), 연락처, 사업자 정보, 언어 목록, 문의 폼 설정 |
| `src/i18n/en.json` | 영어 문구 (기준 파일) |
| `src/i18n/ja.json` 외 4개 | 일본어, 简体中文(zh-cn), 繁體中文(zh-tw), 베트남어(vi), 태국어(th) |
| `tools/` | 빌드 스크립트 (의존성 없음, Node 18 이상) |
| `assets/` | CSS, JS, 폰트, 도장 로고, 공유 이미지 |

`index.html`, `*/index.html`, `404.html`, `sitemap.xml`은 빌드 결과물입니다. 직접 고치지 마세요.

## 고치는 순서

1. 문구: `src/i18n/en.json`과 같은 위치의 각 언어 파일을 함께 고칩니다.
2. 가격: `src/site.json`의 `services[].won`을 고치고, 문구 안의 `{won:56000}` 같은 금액도 맞춥니다. 관리자 견적서 계산기(`__admin__/documents.html`의 `PR`, `SV`)도 같이 고친 뒤 `node tools/check-pricing.mjs`로 사이트 가격과 같은지 확인합니다.
3. 번역 확인: `node tools/check-i18n.mjs ja` (언어마다 실행)
4. 빌드: `node tools/build.mjs`
5. 바뀐 파일을 모두 커밋합니다. main에 올라가면 Vercel이 바로 배포합니다.

## 규칙

- 문구 속 `{price}`, `{won:39000}` 같은 자리 표시는 지우거나 바꾸지 않습니다. 빌드가 이 부분을 채웁니다.
- 원화는 `{won:금액}`으로 씁니다. 언어별 표기(베트남어는 `39.000 ₩`)는 빌드가 처리합니다.
- 번역 파일의 키와 목록 개수는 영어와 같아야 합니다. 다르면 빌드가 멈추고 위치를 알려 줍니다.

## 견적서·인보이스

- 관리자 화면 `__admin__/documents.html`에서 만듭니다. 관리 홈(`__admin__/`)에도 링크가 있고, 로그인은 기존 관리자 계정을 씁니다.
- 처음 한 번 Supabase SQL 편집기에서 `supabase/sql/billing_docs.sql`을 실행합니다. 실행하기 전에는 각자 브라우저에만 저장됩니다. 다시 실행해도 됩니다.
- '기본정보 설정'에 넣어 둔 값이 새 문서에 자동으로 채워집니다: 발행인 정보(한국어·영어), 우리 담당자, 결제기한·유효기한 일수, 입금 계좌, 송금 수수료(OUR). 입금 계좌는 관리자만 읽는 DB에만 저장하고, 저장소가 공개라서 코드와 SQL 파일에는 넣지 않습니다.
- 순서: ① 내용 입력 → ② 한국어·English 미리보기를 각각 보고 체크 → ③ '발행하기' → 언어별 'PDF 저장'. 미리보기는 입력하는 대로 바뀌고, 내용을 고치면 체크가 풀려서 다시 확인해야 합니다. 발행해도 고객에게 메일은 가지 않습니다.
- 한쪽 언어에만 있는 문구(품목 세부사항, 포함·불포함, 취소·환불, 특이사항 등)가 있으면 발행할 수 없습니다. 두 언어 모두 쓰거나 둘 다 비웁니다.
- 발행한 문서는 내용이 고정되고 상태와 내부 메모만 바꿀 수 있습니다(DB에서도 막습니다). 고쳐야 하면 '복제'로 새 번호의 초안을 만들고, 원래 문서는 '무효'로 바꿉니다. 무효는 되돌릴 수 없습니다.
- 확인 질문은 브라우저 팝업이 아니라 페이지 안에서 묻습니다. 저장하는 동안에는 입력란이 잠깁니다.
- 청구 대상: 개인이면 고객 이름, 회사면 회사명과 담당자(문서에는 Attn:)를 넣습니다. 비어 있는 칸은 문서에 나오지 않고, 고르지 않은 유형의 이름은 출력되지 않습니다.
- 통화: USD 문서는 달러가 주 금액이고 원화를 괄호로 함께 적습니다. 원화 단가가 기준이고, 문서의 환율로 바꾼 달러 단가를 품목마다 1달러 단위로 올립니다. 새 문서를 열면 오늘 시장 환율을 자동으로 불러오고(open.er-api.com, 안 되면 frankfurter), 직접 고칠 수 있습니다. 넣은 환율은 소수점까지 그대로 씁니다. 발행한 문서는 그때의 환율과 금액 그대로 남습니다. KRW 문서는 원화만 적습니다.
- 가격 계산기: 서비스를 고르고 '계산기 추가'를 누른 뒤 날짜, 시작 시각, 시간(또는 수량), 옵션, 이동 거리, 크기·무게, 실비를 넣으면 사이트 가격표대로 품목이 자동으로 만들어지고 입력할 때마다 바뀝니다. 한 문서에 계산기를 여러 개 넣을 수 있습니다.
  - 급행(48시간·24시간·당일·3시간 이내)은 요청 받은 시각과 시작 시각으로, 야간(22:00–02:00)은 작업 시간이 그 시간대에 걸치는지로 자동으로 정하고, 직접 바꿀 수도 있습니다. 두 번째 계산기부터는 첫 계산기의 요청 받은 시각과 날짜로 시작합니다. 당일 긴급 배송은 요금에 급행이 들어 있어서 급행이 자동으로 붙지 않습니다. 시간 할증은 서비스 요금(기본 요금과 추가 시간)에만 붙고, 여러 개면 곱합니다(당일 야간 = ×1.35 다음 ×1.3). 옵션, 이동, 크기·무게, 실비에는 붙지 않습니다.
  - 실비는 쓴 금액 그대로 넣고, 실비 처리 수수료 4.5%가 붙습니다(계산기마다 끌 수 있음). 매장 구매·온라인 주문은 서비스 요금에 포함된 물품 처리 수수료 ₩8,000(주문마다)을 넘는 만큼만 더합니다.
  - 계산기가 만든 품목은 품목 목록에서 직접 고칠 수 없습니다. 고쳐야 하면 '직접 고치기'를 눌러 일반 품목으로 바꾸고, 계산기의 '다시 자동으로'로 되돌립니다. 할증이나 실비 수수료의 기준이 되는 줄(기본 요금, 추가 시간, 실비)을 직접 고쳐 금액이 달라지면 경고가 나오니, 금액은 계산기에서 바꿉니다. 계산기 메모는 품목 세부사항에 들어가므로 한국어·영어를 모두 쓰거나 둘 다 비웁니다.
  - 계산기는 만들 때의 가격표를 함께 저장합니다. 사이트 가격이 바뀌어도 저장한 견적서와 그걸로 만든 인보이스의 금액은 그대로이고, 새 가격을 쓰려면 계산기의 '지금 가격으로 다시 계산'을 누릅니다.
- 품목: '추가할 품목'에서 고른 뒤 '품목 추가'. 컨시어지 서비스(일수), 공항 픽업·공항 샌딩(횟수), 공항 픽업 및 샌딩(묶음 1개 = 한 줄), 직접 입력이 있습니다. 품목명·단위·세부사항은 언어마다 직접 고칠 수 있고, 금액은 수량 × 단가입니다. 품목에는 기본 단가가 없습니다. 새 품목 종류는 페이지 코드의 `SERVICES`에 한 줄 추가합니다.
- 세부사항(날짜, 시간, 항공편 시각 등)은 그 품목 아래에만 나옵니다. 특이사항은 선택이고, 비워 두면 제목까지 문서에 나오지 않습니다.
- 번호는 `Q-연도-0001`, `INV-연도-0001` 형식으로 다음 번호가 자동으로 들어가고, 초안일 때는 고칠 수 있습니다. 발행하면 고정됩니다. 한국어·영어 문서는 같은 번호를 씁니다.
- 인보이스의 입금 정보: 은행, 예금주, 계좌번호, SWIFT/BIC, 송금 수수료, 송금 참조(= 인보이스 번호). 발행한 문서는 발행한 날의 발행인·입금 정보를 그대로 간직합니다.
- 'PDF 저장'을 누르면 인쇄 창이 열립니다. 대상은 'PDF로 저장', 여백은 '기본값'으로 둡니다. 문서의 여백이 페이지 여백이라서 브라우저의 날짜·주소 머리글은 붙지 않습니다. 파일 이름 끝에 `_KR`, `_EN`이 붙습니다. 초안을 Ctrl+P로 인쇄하면 '초안' 표시가 크게 찍힙니다.
- 견적서에서 '인보이스로 만들기'를 누르면 같은 내용으로 인보이스 초안이 생깁니다. 선택 품목은 빠집니다.
- 초안만 삭제할 수 있습니다. 발행한 문서는 상태를 '무효'로 바꿉니다.
- 'JSON 내보내기·가져오기'로 문서 내용을 파일로 옮길 수 있습니다. 입금 계좌는 파일에 들어가지 않습니다. 첫 버전(영어만 있던) 파일을 가져오면 안내 문구와 품목 설명은 문서에 넣지 않고 내부 메모로 옮깁니다.

## 문의 폼

- 요청은 Supabase Edge Function `submit-inquiry`로 갑니다 (`is_secret: true`). 관리자 화면 `__admin__/`에서 확인합니다.
- 스팸 방지는 Cloudflare Turnstile입니다. 새 도메인(예: Vercel 미리보기 주소)에서 폼을 시험하려면 Cloudflare 대시보드의 Turnstile 위젯 설정에 그 도메인을 추가해야 합니다.

## 리뷰

- 사이트의 '리뷰' 페이지(`/reviews/`, 6개 언어)에서 누구나 리뷰를 남길 수 있고, 쓰는 즉시 보입니다. 홈에는 최근 리뷰 3개와 평균 별점이 나오고, 리뷰가 없으면 홈 섹션은 숨깁니다.
- 처음 한 번 Supabase SQL 편집기에서 `supabase/sql/reviews.sql`을 실행합니다. 실행하기 전에는 리뷰 페이지에 '불러오지 못했다'는 문구가 보이고 리뷰를 올릴 수 없습니다. 다시 실행해도 됩니다. 예전 사이트가 만든 `reviews` 테이블이 있으면 그 글은 지우지 않고 '숨김'으로 남겨 두니, 관리 화면에서 보일 것만 '다시 보이기' 하면 됩니다.
- 관리는 `__admin__/reviews.html`(관리 홈의 '리뷰' 버튼)에서 합니다. 숨기기, 다시 보이기, 삭제를 할 수 있고, 작성자가 적은 견적서·인보이스 번호는 여기서만 보입니다.
- 스팸 방지: 링크가 들어간 글, 30일 안에 똑같은 글, 10분 동안 10개가 넘는 글은 DB에서 막습니다. 화면에 보이지 않는 칸을 채운 봇은 보내지 않고 끝냅니다.
- 개인정보처리방침에 리뷰 항목(수집 항목, 이용 목적, 보관 기간)이 들어 있습니다.
